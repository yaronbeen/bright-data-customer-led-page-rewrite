# Learnings

- The original fixture predated the final common envelope. Migrating it to `schema_version`, `project`, `observed_at`, status, and record identity fields allowed the undocumented legacy analysis/CLI bypass to be removed.
- Exact question-origin attribution must compare the complete normalized question, including punctuation. A `match_any` hit supports observed language but never makes the operator-authored question verbatim.
- Standalone ATX headings must split into their own blocks even when the following body line is not separated by a blank line; heading blocks cannot serve as answer evidence.
- Public-contributor claims are evidence of selected language only. FAQ answer drafts come exclusively from complete, cited, non-conflicting approved facts; headline templates also contain operator-supplied product and question text.
- Bright Data local caps bound this client, not provider cost. Scraper `202` and transport timeouts must never trigger an automatic retry or poll.
- Running `rtk pytest -q` in this environment reported no tests; use `python3 -m pytest -q` for the repository verification command.
- A fresh local `venv` does not include `setuptools`; an offline install succeeds with `python3 -m venv --system-site-packages ...` and `pip install --no-build-isolation --no-deps .`, using the already installed pinned backend.
- An approval boolean/hash is not a usage counter. Atomic `O_CREAT|O_EXCL` consumption keyed by the complete approval hash prevents both sequential replay and concurrent reuse; uncertain provider outcomes remain consumed.
- Retention limits must include pages and already-retained resume sources, not only requested review/comment counts. Conservative preflight uses the maximum possible retained records, then append checks defend the invariant again.
- Provider-returned record URLs are untrusted metadata. Bind them by canonical URL hash to explicit batch inputs and cite only a redacted approved parent; never retain arbitrary profile or tracker URLs.
- URL query values can carry credentials in vendor-specific or encoded forms. Live page targets reject all queries, dataset routes retain only their narrow required syntax, and every generated artifact redacts all query values regardless of key.
- HTML escaping alone does not make Markdown inert. Untrusted fields must be single-line and escape backslashes, links/images, headings, lists, emphasis, code delimiters, blockquotes, and table pipes.
- `Customer-Led` is a workflow name, not evidence that a contributor is a customer or has buying intent. Generated artifacts must state that distinction near the top.
- Provenance banners must inspect only sources actually cited by output rows. An uncited synthetic source must not label a real-only result synthetic; cited synthetic plus non-synthetic evidence requires a mixed-provenance banner.
- Current Web Unlocker docs conflict: raw-format feature/code examples consume response text directly, while the REST OpenAPI models a `{status_code, headers, body}` object. Until a separately authorized live check resolves this, accepting raw Markdown and rejecting apparent envelopes is more truthful than claiming both shapes work.
- Page-answer matching must stay block-local. Joining body blocks can manufacture an approved sentence that never appeared; output now cites the actual hit block through `page_answer_refs` or `related_copy_refs`.
- A fact's complete supporting quote must preserve normalized case, punctuation, numbers, and qualifiers. Case-folding is appropriate for topic matching, not approval evidence.
- Claim-key conflicts are global across approved facts, not limited to a topic's selected IDs; an unreferenced contradictory approved fact still blocks that claim key.
- Provider failures need durable state, not only exceptions: retain completed sources, mark the current job failed with a safe code, mark later jobs `not_attempted`, and distinguish `failed` from `partial`.
- Collection libraries and resume receipts are executable inputs. Exact schema/project/version keys, counts, job shapes, hashes, and pending-state invariants must be validated before writes, approval consumption, or network.
- Date staleness uses parsed datetimes and a strict `> 30 days` comparison; integer `.days` truncation misses the first stale seconds after the boundary.
- A positive `excerpt_id` alias was left over after migrating the demo to the shared `block_id` citation schema. Remove undocumented aliases unless an actual persisted/external consumer requires them.
- Resume receipts are cumulative libraries: replacing a pending job must preserve prior completed jobs and the original approved-URL hashes. Rehashing a redacted YouTube URL changes its identity and breaks auditability.
- A hit phrase of up to 240 characters must remain entirely inside its cited excerpt. A generic 240-character window can clip the matching fact near the end and produce a citation that does not prove the answer.
- Provider metadata IDs follow the shared string contract; booleans should not be stringified as record IDs merely because Python treats bool as int.
- The same page character limit applies to live collection and local Markdown import; input file size and normalized source-character limits are separate checks.
- Resume must preserve the original pending job's approved URL hash when updating job state. Recomputing it from a redacted URL changes the identity; a resumed receipt is cumulative across calls and retained sources.
- When optional `--sources` is provided, validate the base analysis document before inspecting nested source IDs. Otherwise malformed JSON-shaped input can raise raw `KeyError`/`TypeError` instead of a structured validation error.
- A source citation excerpt must contain the complete matched phrase. For phrases at the end of a long block, position the <=240-character window to retain the full evidence span.
- An attached collection receipt can describe pending/empty/failed/not-attempted work even if it contributes no Source rows. CLI analysis must carry that uncertainty into report status and Markdown warnings rather than returning false `no_data`.
- Detached CSV exports need provenance at the row level. Compute synthetic/mixed/non-synthetic state from each row's own cited source IDs, not from a report-wide banner or uncited sources; use explicit `unknown`/`uncited` states instead of implying real evidence.
- Resume receipts redact URL query values, so bind each safe URL representation positionally to its exact approved-target SHA-256; validate every pair and directly rehash every unredacted stored URL (including every Amazon URL) before any resume request.
- Provider record IDs are untrusted strings and may look like credentials. Use raw values only transiently for duplicate/conflict matching, then persist a deterministic SHA-256-derived opaque ID; reapply this at analysis input normalization so older or supplied libraries cannot leak raw provider IDs into reports.
- An unkeyed digest over a redacted URL plus its stored target hash does not authenticate the target hash; both can be recomputed after tampering. Fail closed when the canonical URL is unavailable, and compare each stored URL hash directly with each canonical URL wherever the receipt retains it.
- For JSON receipt validation, type-check strings before set membership and validate each hash list independently before any combined operations; catch residual structural type/key errors at the validator boundary and normalize them to `invalid_receipt` before network or approval use.
